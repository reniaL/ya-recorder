### UX-05：文件夹手工排序（方案确认，2026-10-06）

已确认支持按使用习惯调整文件夹顺序，采用“进入排序模式 → 拖动调整 → 点击完成保存”的方案。确认方案时实现按名称排序、数据库尚无自定义顺序字段；实现结果见本节末尾。

- 文件夹管理页顶部增加“排序”，至少有两个文件夹时可用。进入后显示“取消”“完成”及“拖动右侧手柄调整顺序”提示，每行右侧显示拖动手柄。
- 从手柄拖动调整位置，其他行随位置变化让位，靠近屏幕边缘时自动滚动；普通滑动用于浏览。排序期间收起创建、重命名和删除入口。提供辅助功能上移/下移操作及行菜单中的“上移”“下移”，让无法拖动的用户也能调整顺序；首尾对应操作禁用。
- “完成”一次性保存并退出；取消或系统返回放弃本次调整，未改动时直接退出。保存期间显示进度并禁用重复提交与退出；失败保留调整后的顺序，提示“无法保存文件夹顺序，请重试”，允许重试或取消。
- 文件夹管理、主界面范围选择器、单条及批量移动选择器统一使用保存顺序。“全部录音”在包含该项的选择器中固定第一项，不参与排序；移动目标沿用现有过滤规则。
- 新文件夹追加末尾；重命名保持位置；删除后保留其余文件夹相对顺序。升级时以现有名称排序（`name COLLATE NOCASE ASC, id ASC`）初始化。录音仍按创建时间倒序，当前所选范围不因排序改变。
- 存储方案为文件夹表增加 `sort_order`，统一查询顺序；数据库事务校验提交的文件夹 ID 无重复、遗漏或失效，再更新整组顺序，失败整组回滚。数据库升级保留文件夹、录音归属和音频文件。

验收覆盖连续拖动、跨屏拖动、取消与系统返回、未改动退出、保存失败及重试、各选择器顺序一致、重启持久化、创建/重命名/删除后的顺序、旧数据库升级不丢数据，以及窄屏、大字体、长名称和无障碍替代操作。自动化检查验证事务、升级和交互，真机确认拖动与边缘滚动体验。

已同步功能列表、交互设计、用户流程及开发进度，作为新增 MVP 文件夹能力跟踪为 `UX-05`，在 UX-04 之后实施。

实现记录（2026-10-06）：已落实排序模式、手柄拖动与边缘滚动、上移/下移菜单及无障碍操作、完成保存与取消/系统返回。保存期间禁用调整、重复提交与退出，失败保留调整供重试或取消。数据库版本 2 增加 `sort_order`，升级保留原名称顺序；完整 ID 校验及整组更新使用事务。范围及单条/批量移动选择器共享顺序；新建追加、重命名保持位置、删除保留相对顺序，录音元数据与音频不因排序改变。新增 3 项存储测试及 5 项组件测试覆盖升级、重启、文件与元数据、无效 ID、中途写入失败回滚、拖动/取消/系统返回/未改动退出/失败重试/提交禁用、各选择器顺序、窄屏两倍字体长名称、无障碍替代操作与边缘滚动。`flutter analyze` 无问题，`flutter test`（101 项）通过。当前未连接 Android 设备，实际拖动、跨屏滚动及屏幕阅读器体验待真机回归，开发状态保留“进行中”。

### UX-04：当前目录标题可读性（方案确认，2026-10-06）

当前实现使用未单独设置文字样式的 `TextButton.icon` 显示目录名称，沿用按钮排版，且下拉箭头位于文字前方。已确认将当前目录呈现为清晰的页面标题，同时保留点击切换范围的交互。

- 默认字号为 20 逻辑像素，跟随系统字体缩放；字重为半粗体（`w600`），颜色使用主题主要文字色。以 20 为首版实现基准，若真机验证仍偏小，再评估 22。
- 名称左对齐，与列表内容左侧起点尽量一致；下拉箭头移到名称右侧，例如“全部录音 ▾”“工作访谈 ▾”。名称与箭头整体可点击，触控高度至少 48 逻辑像素。
- 长名称保持单行并在超长时省略，箭头始终可见；范围选择器支持查看完整名称，无障碍标签保留完整名称并说明“切换录音范围”。
- 搜索框替换标题时，提示显示“搜索全部录音”或“搜索「工作访谈」中的录音”，随当前范围更新；不改变搜索范围与筛选规则。
- 保持紧凑顶部布局，不新增常驻目录栏或录音数量副标题；多选与范围切换行为沿用现有规则。

验收要求：默认字体下当前目录具有清晰的标题层级；320 逻辑像素宽、两倍字体及长名称下，标题、箭头与右侧操作不重叠，目录入口容易点击；范围选择器和无障碍标签可获得完整名称。验证切换目录、多选、搜索及关闭搜索后的标题恢复，并检查浅色、深色下的可读性。实现后以组件测试及静态分析验证布局与交互，再通过真机判断字号和视觉分量。

方案已同步至交互设计、用户流程和开发进度；不改变 MVP 功能范围与计数。

实现记录（2026-10-06）：已落实标题样式、右侧箭头、至少 48 的触控高度、长名称省略及完整无障碍名称和切换操作；范围选择器改为可滚动列表，长名称可完整查看。搜索提示使用当前范围名称，关闭后恢复标题。新增 2 项组件测试覆盖 320 × 640、两倍字体、长名称及浅色/深色，验证布局无重叠、触控高度、完整语义、范围切换、搜索与多选；默认字体沿用既有回归覆盖。`flutter analyze` 无问题，`flutter test`（93 项）通过。当前无连接的 Android 设备，字号与视觉分量、实际触控及屏幕阅读器体验待真机回归，开发状态保留“进行中”。

### UX-01：底部录音按钮与播放器重叠（2026-10-05）

原布局问题已确认：`lib/main.dart` 的录音列表将播放器放入 `Scaffold.bottomSheet`，同时显示 `FloatingActionButton.extended`，未设置自定义悬浮位置。当前本地 Flutter SDK 的默认 `endFloat` 布局在存在底部面板时，将按钮顶部设为面板顶部减去半个按钮高度，因此按钮下半部分覆盖播放器顶部。列表的底部 `padding: 176` 只为列表内容留白，不会改变按钮与播放器之间的位置关系。

修复前的临时组件诊断测试在 390 × 844 逻辑像素、默认字体、无底部系统安全区的视口下测得重叠高度为 28（按钮高度 56 的一半），横向重叠位于播放器右侧。

现将播放器与录音按钮统一放入 `Scaffold.bottomNavigationBar`，播放器在上、按钮在下方右侧，间隔 16 逻辑像素，外层统一处理底部安全区。列表随底部区域实际高度缩小，移除固定 176 留白；多选仍隐藏两者。为避免窄屏两倍字体下播放器横向溢出，进度条独占一行，时间与播放控制放在另一行。

新增 2 项组件回归测试覆盖 390 × 844 默认字体及 320 × 640 两倍字体、34 逻辑像素底部安全区：验证播放器与按钮不相交、上下间距、列表末项完整可见、多选隐藏与退出恢复，以及停止播放后的列表高度恢复。`flutter analyze` 无问题，`flutter test`（54 项）通过；尚未进行真机操作回归。
