## 2. 架构分工与实现原则

建议新增 `lib/backup/`，集中协议模型、任务协调、导入导出服务和页面；具体文件名可在实现时按职责细分。

- Flutter：产品规则、快照与合并计划、SQLite 事务、任务状态和页面；不在页面内持有长任务。
- 后台工作执行器：流式 ZIP、SHA-256、分块复制和取消检查；独立于 UI 生命周期。禁止把整批音频作为字节数组跨桥传递。
- Android：文档选择器、URI 流访问、前台任务及通知、平台错误回传。单独使用备份任务服务，不将备份伪装为麦克风录音服务。
- 存储层：写入保护、完整快照、包括最近删除的查重、合并事务和提交标记。业务门禁不等于长期 SQLite 写事务，浏览、播放和设置仍可使用。

第三步验证 Dart 工作 isolate 与前台宿主/FlutterEngine 的生命周期、平台桥连接方式；如果采用原生流式工作执行器，SQLite 的权威写入仍保持单一接口。实施时固定一种执行路径并记录决策，不能仅启动一个空前台服务就宣称任务与 Activity 生命周期解耦。

第一步已锁定 archive 4.5.2、crypto 3.0.7、uuid 4.6.0，流式/ZIP64 的真实大包适配验证仍留在第四/五步；选型和限制见 [第一步记录](manual-backup-step1.md)。优先成熟库，不自制随机 UUID 或 ZIP 编解码。Android 文档访问可以使用原生桥，避免无必要的通用存储权限。

## 3. 第一步：备份契约与 UUID（BKP-01）

工作内容：

1. 固定备份格式 v1：标识、UTC 时间、录音和文件夹字段、相对路径、大小、SHA-256；JSON 不包含设备绝对路径和应用设置。
2. 定义 manifest 对 metadata 和音频的校验覆盖，不要求 manifest 对自身递归校验；文件清单和实际条目一一对应。
3. 定义可接受的 ID、格式、字段长度、文件数量和解压总量等限制，记录实际数值及理由。限制属于导入资源保护，不改变录音时长范围。
4. 拒绝重复 ID、重复/越界路径、非法条目、无效文件夹引用、不支持版本和加密包；处理 ZIP64，或明确拒绝超出实现能力的包，不能静默截断。
5. 新文件夹使用 `folder-<UUID>`，旧时间戳 ID 不迁移；备份保留所有合法 ID。
6. 准备三格式、小型/空库、旧 ID 和冲突元数据的测试夹具，定义错误码和阶段进度契约。

交付与关口：协议说明和可测试解析器、UUID 接入、版本/路径/字段校验测试。运行静态分析、协议/存储/文件夹相关测试；新增依赖时按影响执行全量 Flutter 回归，平台依赖变更则构建 APK。验证旧 ID、录音归属和重启读取不变。

## 4. 第二步：任务协调与数据保护（BKP-02）

工作内容：

1. 建立应用级协调器和单任务租约，含任务 ID、类型、阶段、取消能力、结果与错误；任务不绑定进度页。
2. 开始前排空或拒绝未结束的录音保存/恢复写入，原子地进入保护状态；录音开始也通过同一协调机制，覆盖权限授权后延迟启动的竞态。
3. 存储业务入口保护新录音、录音及文件夹管理、最近删除恢复/永久删除。不得仅禁用 UI 按钮。
4. 接入 `RecordingSaveCoordinator`、启动/回前台恢复、`purgeExpiredRecordings` 和最近删除页的自动清理：任务期间延后写入，结束后安全重试；不丢弃原生 fileReady 或确认前的草稿。
5. 提供短事务读取正常录音和全部文件夹的快照，以及含软删除记录的 ID 查询；备份内部写入使用协调器授权，不绕过公共入口形成任意可写后门。
6. 释放锁时恢复操作能力并刷新列表，所有异常和取消路径均释放；启动时先处理未完成备份任务，再执行会改变文件的录音恢复和清理。

交付与关口：可独立测试的门禁、快照和生命周期协调；活动/暂停/准备/保存录音拒绝备份，两任务并发拒绝。覆盖异步开始、后台回调、自动清理、最近删除和取消竞态。共享保存保证受影响，运行静态分析及全量 Flutter 测试；涉及原生门禁则运行相关 JVM 测试并构建 APK。

## 5. 第三步：平台文件与长任务基础（BKP-03）

工作内容：

1. 文档选择使用 `ACTION_CREATE_DOCUMENT` / `ACTION_OPEN_DOCUMENT`，返回 URI 和显示名称；Picker 取消不进入数据保护状态。
2. 分块读写 URI，不假定磁盘路径、seek 能力或目标空间可查询；源需要 seek 时先流式暂存到任务私有目录。
3. 独立前台任务使用适当的 `dataSync` 类型和权限，从用户前台操作启动；通知展示阶段、进度、重新进入和取消，不申请麦克风权限。
4. 定义页面关闭、Activity 重建、通知拒绝、服务启动失败、系统超时与进程终止的状态和清理，禁止开机自动续传。
5. 状态和事件带任务 ID/序号，重新订阅先获取快照，忽略旧任务的迟到事件；进度更新节流，取消在分块边界执行。
6. 记录任务目录和目标 URI，支持读写失败及尽力删除半成品；不能删除时回报残留目标，不修改用户选择之外的文件。

等待导入确认期间不运行重计算；界面和协调器保留等待状态。不能为无限等待依赖无限期前台服务：停止工作服务或明确处理服务时限，用户回前台确认后重新启动执行，进程终止则按未提交任务清理。

交付与关口：小型流式复制探针即可，尚不开放正式导出入口。JVM/桥接与取消测试、全量 Flutter 回归、APK 构建；真机验证选择器、URI 权限、通知、前后台和锁屏，不以模拟普通路径替代文档服务验证。

## 6. 第四步：完整导出（BKP-04）

工作内容：

1. 基于受保护快照统计正常录音与空文件夹，排除最近删除、草稿和设置。
2. 校验源文件存在、格式和大小；缺失或不一致时整体失败，不能生成看似完整的备份。
3. 在私有任务目录流式生成 ZIP，音频使用 STORE，不重新编码；写入 JSON、清单及校验值，关闭 ZIP 后复核结构和内容。
4. 复制完整临时包到目标 URI，成功关闭目标输出后再报告成功；导出检查、打包、保存分别显示进度。
5. 估算源读取、临时包和本地目标副本的空间需求；未知目标容量明确不可预检，处理中正常处理空间错误。
6. 取消或失败清理任务文件及目标半成品；成功后按分享生命周期保留必要临时副本，避免目标应用尚未读取即删除。

交付与关口：生成可用 v1 包并独立读取校验，三格式哈希一致、空库可导出、取消/写入失败不产生成功。静态分析、导出及门禁相关测试；跨层集成执行全量回归和构建。真机验证大量文件、保存失败、空间不足及后台取消。

## 7. 第五步：合并导入与中断恢复（BKP-05）

工作内容：

1. 暂存源包并验证所有条目，包括本地已存在的录音；损坏或缺失整包拒绝，预览前不修改业务数据。
2. 用所有本地录音 ID（含最近删除）生成导入计划：同 ID 跳过、不同 ID 导入；区分重复和差异跳过只影响统计。已有 ID 无可校验音频等本地异常应明确报告，不覆盖修复。
3. 生成文件夹映射：同 ID 沿用；不同 ID 同名按当前 SQLite 名称唯一规则递增后缀；本地顺序保持，新文件夹按备份顺序追加。
4. 准备新音频到专用暂存目录，保留原 ID，重建目标路径；发现无索引但已占用目标路径的孤立文件时拒绝，不覆盖。
5. 引入持久化任务清单，逐个将新文件就位，最后一个数据库事务插入文件夹、录音和导入提交标记。若使用内部提交表，按现有 SQLite v7 新增迁移，不重建既有 ID 或音频。
6. 进程终止后以数据库同事务的提交标记为权威：未提交清理本任务新文件；已提交保留音频，仅清理暂存和日志。不能仅凭事务外 journal 的 COMMITTED 字样判断结果。
7. 明确日志与提交标记清理顺序；删除失败留待重试，只处理有本任务归属证明的文件。无法判定归属时保留并报告，不冒险删除。
8. 提交前可取消，短提交阶段不可取消；无新增录音但有新空文件夹也可成功，完全重复明确报告无新增。

交付与关口：合并引擎、数据库原子提交和恢复记录。故障注入覆盖每次文件就位、事务内中途、提交后未写 journal、清理中断，验证不误删已提交文件且原数据不变。静态分析、全量 Flutter 和受影响 JVM 测试、APK 构建；真机验证实际进程终止及重启。

## 8. 第六步：完整交互与本地化（BKP-06）

工作内容：

1. 设置新增“备份与恢复”，提供导出、导入、当前任务入口，不新增主导航。
2. 导出摘要显示范围、数量、大小及未加密说明；导入预览显示新增、重复、冲突和改名文件夹，用户确认后执行。
3. 进度页可离开，不因返回取消任务；等待确认可返回并重新进入，提供明确取消入口及数据保护说明。
4. 主界面和各管理页解释操作禁用原因；导入完成刷新列表和所有文件夹选择器，不打断允许的浏览/播放。
5. 结果页保留可查看结果和失败原因，提供分享或重新开始。录音 ID 冲突没有覆盖/副本选择。
6. 中英文、复数、浅深色、窄屏、两倍字体和无障碍覆盖页面与通知；切换语言/主题不重启任务。

交付与关口：完整入口、页面与通知联动。静态分析、相关 widget/本地化测试；共享状态集成运行全量 Flutter，通知平台改动运行 JVM/构建。真机检查系统返回、手势、通知重新进入及实际操作禁用。

## 9. 第七步：回归与发布验收（BKP-07）

工作内容：

1. 按第一版设计的十项验收建立清单与证据快照，记录设备/系统、数据集、文件数量、容量、耗时和结果。
2. 在无原数据的新设备或隔离应用环境恢复，检查三格式播放、标题/时间、归属与排序；不清空用户真实库作为测试准备。
3. 验证重复/交叉导入、最近删除 ID 跳过、同名不同 ID、空文件夹及新旧文件夹 ID。
4. 验证损坏包、路径攻击、空间不足、源/目标权限失效、取消和前后台/锁屏/进程终止。
5. 使用许多短录音及不同大小文件验证流式资源占用和字节进度；备份大容量验收不要求新增一小时录音测试。
6. 回归原录音保存/恢复/取消、最近删除清理、播放、分享、主题、语言和数据库升级；确认没有新云端权限或上传行为。

验证：最终代码完成后一次完整静态分析、全量 Flutter、受影响 Android JVM 测试与普通 debug APK 构建；后续更改按影响重新验证。缺少设备时保留真机待验收状态，不用构建通过替代换机恢复证据。
