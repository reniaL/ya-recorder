# 手动备份与恢复：第一版设计

确认日期：2026-10-15。

状态：用户已确认第一版方案，2026-10-15 已同步产品范围和开发进度。第一步协议及文件夹 UUID 已完成，完整导入导出尚未实现。本文作为开发与验收依据；分步交付见 [七步实现计划](manual-backup-and-restore-implementation-plan.md)，各项验证以对应记录为准。

## 1. 目标与范围

用户可以将正常录音及其分类信息导出为一个 ZIP 备份包，并在原手机或新手机上导入恢复。恢复默认合并，保留现有数据；遇到已有录音 ID 时跳过，不提供覆盖或保留两份选项。

第一版包括：

- 手动全量导出一个 ZIP，用户选择保存位置。
- 手动选择 ZIP 导入，无需用户解压。
- 任务进度、取消、失败说明及结果统计。
- 切换应用或锁屏时通过 Android 前台任务及通知尽量维持执行。
- 内容完整性验证、空间检查、导入失败回滚及中断清理。

第一版不包括：加密、增量备份、自动备份、云端接口、多设备同步、断点恢复、覆盖导入、冲突副本，以及普通音频文件或任意 ZIP 的导入。

备份保存在同一部手机上不能覆盖整机丢失或损坏风险。导出成功后提示将文件复制到电脑、外置存储或网盘。

## 2. 已确认的数据规则

| 项目 | 规则 |
| --- | --- |
| 正常录音 | 导出全部已完成且未处于最近删除状态的录音，保留原音频格式 |
| 录音元数据 | 保留 ID、标题、时间、时长、格式、文件大小、文件夹归属及中断标记 |
| 文件夹 | 保留 ID、名称及排序，包括空文件夹 |
| 最近删除 | 不导出；导入查重仍检查本地最近删除中的 ID |
| 未完成录音及草稿 | 不导出，不混入正常录音备份 |
| 应用设置 | 不导出；导入后沿用手机现有设置 |
| 加密 | 第一版不加密，导出界面明确备份包含原始音频及录音信息 |
| 导入方式 | 合并；备份中不存在的本地录音和文件夹保持不变 |
| 录音冲突 | 本地存在相同 ID 时直接跳过，不修改音频、标题或归属 |
| 文件夹冲突 | 同 ID 沿用本地文件夹；不同 ID 同名时新建并自动添加名称后缀 |
| 数据修改 | 导入、导出任务执行期间禁止修改相关数据，允许浏览和播放 |

## 3. ID 与兼容性

录音沿用已有随机 UUID。新建文件夹改用 `folder-<UUID>`；已有 `folder-<时间戳>` ID 保持不变，不迁移、不重写录音关联。

备份与恢复都将 ID 视为不透明字符串，接受合法的旧 ID 和新 ID，保留原值。ID 格式变更本身不要求数据库结构升级；这不代表任意旧版应用都能读取新版数据库或导入新备份格式。

录音查重只使用 ID，不使用标题或文件名：

- 同 ID，即使内容或元数据不同，也跳过。
- 不同 ID，即使标题相同或音频内容相同，也作为不同录音导入。
- 重复导入同一备份，不产生重复录音。
- 同 ID 存在于本地最近删除时跳过，不将其自动恢复。

结果统计可以区分“重复跳过”与“差异冲突跳过”，但二者处理相同，无需用户选择。音频校验用于验证内容及识别差异，不改变按 ID 跳过的规则。

## 4. ZIP 格式

建议文件名为 `丫丫录音备份-YYYYMMDD-HHmmss.zip`，时间按用户设备本地时间生成；包内时间使用明确的 UTC 格式。

```text
丫丫录音备份-20261015-143000.zip
├── manifest.json
├── metadata.json
└── recordings/
    ├── recording-<ID>.aac
    ├── recording-<ID>.mp3
    └── recording-<ID>.m4a
```

- `manifest.json`：应用备份标识、备份格式版本、创建时间、条目数量、相对路径、文件大小及 SHA-256 校验值；校验范围包含元数据和音频。
- `metadata.json`：录音及文件夹信息，保存必要的归属关系和排序。
- `recordings/`：音频原样存放，不转换格式。音频采用 ZIP 不压缩存储方式，避免不必要的重复压缩。

不直接复制正在使用的 `index.db`。导出版本化 JSON，导入时使用当前数据库结构重建索引。索引中的原手机绝对路径不写入可恢复路径字段；备份使用相对路径，恢复时生成当前手机的绝对路径。

校验值用于发现损坏，不提供加密或防篡改身份认证。任何拿到未加密备份包的人都可能读取音频及标题。

## 5. 导出流程

1. 从“设置 → 备份与恢复”进入，点击“导出备份”。
2. 展示正常录音数量、音频总大小、备份范围及未加密说明。预计 ZIP 大小和所需临时空间单独说明，不能将音频大小直接当作精确空间需求。
3. 用户通过系统文件选择器指定位置及文件名。取消选择时不开始任务。
4. 获取任务锁，检查是否有活动录音、待完成的保存或恢复写入；不满足时提示稍后重试。
5. 进入数据保护状态，获取一致元数据快照，分块读取音频、计算校验值并生成 ZIP。
6. 完成 ZIP 写入、关闭和必要完整性检查，再保存到目标位置。空间需求应覆盖所采用流程中的临时包和目标副本。
7. 展示成功结果、文件名和位置，释放锁，提供分享入口及保存到手机之外的提示。

用户选择的文件位置由 Android 文档接口处理，不假定一定是普通文件系统路径。第一版的必要目标是用户可选择的本地存储；外置设备或文档服务是否可用取决于设备环境。

写入目标失败时不得显示成功。半成品尽力删除；无法删除时明确提示其位置及不可用状态。通过目标应用分享文件，只报告交接结果，不报告远端上传成功。

## 6. 导入流程与文件夹规则

1. 点击“导入备份”，通过系统文件选择器选择应用生成的 ZIP。
2. 获取任务锁及数据保护状态，检查来源、版本、条目、校验值、空间和元数据关系。
3. 展示备份时间、待新增数量、重复数量、差异冲突数量，以及文件夹自动改名提示。
4. 用户确认后分块准备待导入文件，生成当前手机路径并重建索引。
5. 文件准备完成后统一提交索引；展示新增、重复跳过、冲突跳过数量，释放锁。

预检查阶段已开始任务，数据保护持续到用户取消或任务完成；确认页面说明暂时禁止修改数据，避免用户长时间停留而不理解原因。任务开始时仍需检查活动录音及其他写入。

文件夹处理：

- 同 ID 已存在：沿用本地文件夹及名称、排序；新增录音指向该文件夹。
- ID 不存在且名称可用：保留备份 ID 和名称，新建文件夹。
- ID 不存在但名称冲突：保留备份 ID，名称依次尝试 `原名称（导入）`、`原名称（导入 2）`，直到满足数据库名称唯一规则。
- 本地文件夹顺序保持；新增文件夹按备份相对顺序追加在后面。
- 无文件夹归属的录音继续无归属；引用包内不存在的文件夹等结构错误应拒绝导入。

即使某文件夹下所有录音都被跳过，新文件夹仍按备份记录恢复，以保持空文件夹恢复规则一致。再次导入时按 ID 识别，不反复创建文件夹。

## 7. 长时间任务、数据保护与取消

### 7.1 执行与进度

打包、校验、复制等耗时工作在后台执行，采用流式处理；不将全部音频加载到内存，不阻塞界面。

导出阶段显示“准备备份 → 打包文件 → 保存备份”；导入显示“检查备份 → 等待确认 → 导入文件 → 完成入库”。每个阶段分别显示状态，能计算总量时提供阶段百分比，不能计算时显示活动状态。

百分比以实际处理字节数为主，条数为辅助。例如“正在打包：65%；325 MB / 500 MB，48 / 76 条”。阶段转换时明确说明，不用虚假总进度掩盖最后保存耗时；未完成全部工作前不显示成功。

用户可离开进度页，通过设置页任务状态或通知重新进入。Android 前台任务及通知维持长时间工作；需在目标 Android 版本验证通知、锁屏和后台限制。系统终止后不承诺自动续传，重新打开应用说明中断并允许重新开始。

### 7.2 数据保护

同时只运行一个导入或导出任务。活动录音期间不允许开始任务。

任务期间禁止：新录音、重命名、移动、删除、恢复或永久删除录音，以及创建、重命名、排序和删除文件夹。浏览和播放仍可使用。

限制必须在业务写入入口生效，不能只禁用页面按钮。过期清理、草稿恢复入库和其他自动写入同样需要协调，确保任务期间数据稳定；应用设置不属于备份范围，可继续调整。

### 7.3 取消与中断

提供取消入口，点击后显示“正在取消”，在安全边界停止并清理任务产物。导入提交索引的短暂阶段不可取消，并显示“正在完成导入”。

取消、失败及系统中断不修改原有录音。重启时识别任务状态，清理未提交临时文件，恢复可操作状态，不把半套文件当作成功恢复。

## 8. 一致性与失败处理

- 备份格式不支持、必要字段缺失、条目重复、文件缺失或校验失败：整包拒绝导入，不提供忽略错误继续选项。
- 所有包内文件均做必要验证，即使其录音 ID 在本地已存在；避免将损坏包报告为正常备份。
- 拒绝越界路径及异常条目，限制解压大小和数量，防止外部 ZIP 造成非预期写入或资源耗尽。
- 导入先准备新文件，后统一提交索引；失败时回滚并清理新文件，不能删改已有音频。
- 文件系统与 SQLite 不具备共同事务，需要设计任务记录或等价恢复机制，处理文件就位后、索引提交前后进程终止的边界。
- 索引提交成功后才将导入标记为成功。提交后的临时清理失败应保留成功结果并安排后续清理，不能误回滚已提交音频。
- 本地存在孤立文件或索引与文件不一致时，不盲目覆盖；明确报告异常，保护已有文件。
- 所需空间按实际实现路径估算，预检查不能替代处理中对存储不足的错误处理。

## 9. 用户可见结果

| 状态 | 表达要求 |
| --- | --- |
| 导出成功 | 显示文件名、位置、数量；提示保存到手机之外 |
| 导入成功 | 显示新增、重复跳过、冲突跳过数量及文件夹改名结果 |
| 全部已存在 | 明确说明没有新增录音，不能误报失败 |
| 用户取消 | 显示已取消，现有数据保持不变 |
| 备份无效或损坏 | 说明检查失败原因，未导入任何数据 |
| 空间不足或写入失败 | 说明原因并提供重新开始入口 |
| 系统中断 | 重新打开后说明上次任务未完成或已提交的实际结果 |

不将导出到手机或分享交接成功描述为异地备份完成。第一版不要求自动提醒、备份历史管理或远端状态。

## 10. 验收要求

核心验收：在没有原应用数据的新手机上，导入 ZIP 后能够恢复正常录音、标题、时间、文件夹及排序，音频可以播放，应用设置保持当前手机的值。

至少验证：

1. AAC、MP3、旧 M4A、中文与英文、长标题、同名录音和空文件夹。
2. 排除最近删除及草稿；已恢复保存为正常记录的中断录音正常导出。
3. 相同备份重复导入、不同备份交叉导入，以及本地最近删除中的同 ID 跳过。
4. 同 ID 音频或元数据不同仍跳过；不同 ID 同名或同内容正常导入。
5. 文件夹同 ID 沿用、不同 ID 同名改名、名称后缀已有时继续递增及新旧 ID 混用。
6. 文件缺失、校验失败、非法路径、不支持版本、重复条目及元数据关系错误时整包拒绝。
7. 较多录音和较大总容量下进度合理、界面流畅，取消及空间不足正确处理。
8. 导入、导出期间所有手动和自动写入均受保护，浏览与播放可用。
9. 前后台切换、锁屏、页面关闭、进程终止及重启清理；验证索引提交前后的恢复边界。
10. 任务失败后原有数据完整、无半套可见记录，成功后音频校验值与备份一致。

确认范围已同步到产品功能列表、用户流程、交互设计及开发进度；第一步协议基础已完成，其余工作项未开始，实现时依据改动影响执行自动化检查和 Android 真机验收。
