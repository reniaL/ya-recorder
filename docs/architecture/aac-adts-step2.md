## 格式契约

Dart 与 Kotlin 的 `RecordingFormat` 增加 `aac`，对应 `.aac` / `audio/aac`。最终文件为 `recording-<id>.aac`，临时文件为 `recording-<id>.aac.part`。已有 `m4a` / `audio/mp4` 与 `mp3` / `audio/mpeg` 的值保持；路径、模型、状态和原生协议沿用已有格式解析，不增加转换逻辑。

原生可录能力列表仍为 M4A、MP3；AAC 格式已知但编码能力暂不可用，开始命令在创建录音器前拒绝，不回退到 M4A。设置选择器沿用原生能力判断，AAC 项不可选择。对于初始或升级得到的 AAC 默认值，开始时显示对应中英文不可用提示，保留偏好并允许用户主动选择 M4A 或 MP3 重试。此行为已通过 widget 与原生测试；第三步接入后端后再开放能力。

## SQLite 版本 7

- 版本从 6 升至 7；`recordings.format` 和 `recording_preferences.default_format` 的 CHECK 允许 `m4a/mp3/aac`。
- 使用 sqflite 的 onUpgrade 事务，建新表、按显式列复制、替换旧表并重建两个录音索引；不修改 sqlite_master、不增加手工回滚或重试层。
- 录音表只有指向 folders 的外键，没有其他表引用 recordings；迁移不删除父表，foreign_keys 全程开启。保留唯一文件路径、非负时长/大小、删除/中断状态约束及文件夹删除时置空语义。
- 录音行的格式、路径、标题、时间、时长、大小、文件夹和删除/中断状态逐列保留。录音表 SQL 的缺省 format 仍为 m4a，以保留旧索引语义；应用保存录音始终显式传入实际格式，该缺省值与新录音偏好默认值是两件事。
- 新安装及没有格式偏好的升级用户默认 AAC；已有 M4A 偏好迁移为 AAC，MP3 偏好保持。空偏好表保留为空，由读取逻辑返回 AAC，不新增无必要的偏好行。
- 未改变音频、原生草稿及临时文件；主题、语言、文件夹顺序保持。旧 M4A 草稿继续按 m4a 解析，不对其格式做替换。
- 未知/损坏偏好不映射为默认格式；迁移约束失败回滚整个升级，版本、原表、数据及约束保持，可修复后重试。
