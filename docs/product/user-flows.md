# 用户流程

本文描述丫丫录音 MVP 的用户操作流程和关键结果。它用于指导交互设计、功能实现与验收；具体视觉样式、控件位置和文案可在 UI 设计阶段细化。

## 全局约定

- 主界面以录音列表为核心，并提供始终易于触达的开始录音入口。
- 录音尚未停止并安全保存前，不将它作为普通录音显示在列表中。
- 一次只能存在一条进行中的录音，也只能播放一条录音。
- 所有会丢失数据的操作均需明确确认；用户取消确认后保持原状态。
- 用户主动分享、永久删除和前往系统设置会离开应用当前流程；返回后应尽量恢复上下文。

## 快速录音

1. 用户在主界面触发开始录音。
2. 若尚无麦克风权限，应用请求系统权限。
3. 获得权限后，应用准备录音并进入录音中状态，显示录音时长与暂停、停止、取消操作。
4. 用户选择停止时，应用完成音频封装、写入文件和索引。
5. 保存成功后，应用返回录音列表或保存结果视图；新录音以默认标题显示在当前文件夹或全部录音中。

成功标准：用户从开始到看到可播放的新录音，不需要输入名称、选择目录或登录。

正常保存成功的顶部提示约 4 秒后自动消失，用户也可手动关闭；异常中断的保存结果应明确说明中断和已录部分的去向，不使用普通成功提示的自动消失规则。

## 权限被拒绝

1. 用户触发开始录音，系统拒绝麦克风权限。
2. 应用不创建录音条目或空文件。
3. 应用说明录音需要麦克风权限，并提供再次请求和前往系统设置的入口。
4. 用户不授予权限时，仍可浏览、播放和管理既有录音。

## 暂停与继续

1. 录音中用户选择暂停。
2. 界面切换至已暂停状态，已录时长保持不变，并突出继续与停止操作。
3. 用户选择继续后，应用回到录音中状态，并向同一录音继续写入。
4. 用户停止后，暂停前后内容作为一条完整录音保存。

若继续录音失败，应用保留已经录下的部分，按录音生命周期中的异常策略完成保存或告知用户结果。

## 取消未完成录音

1. 录音中或已暂停时，用户选择取消。
2. 应用提示该操作会放弃当前尚未保存的录音。
3. 用户确认后，应用停止录音、删除临时数据并返回此前页面。
4. 用户取消确认后，继续保持原录音状态。

确认放弃完成后显示“本次录音已放弃”，约 4 秒后自动消失，也可手动关闭。连续成功提示只显示最新一条并重新计时；开始下一次录音清除此前提示。

## 回放录音

### 在列表中快速回放

1. 用户点击录音行的播放按钮，在列表内播放并显示简洁底部播放器，不打开详情；再次点击暂停或继续。
2. 用户可查看标题、当前位置和总时长、拖动进度。倍速选择和快进/快退操作放在详情页。
3. 点击另一条录音的播放按钮时，停止当前播放并切换为新录音。

### 在详情页专注回放

1. 用户点击录音标题或录音行其余区域，进入独立详情页并立即自动播放；也可点击底部播放器标题进入。多选模式下行点击仍仅切换选择。
2. 若所选录音已在播放或暂停，保留当前位置与倍速并继续播放；选择另一条则停止原播放，从新录音起点播放。两个界面共用一个播放状态。
3. 用户可播放/暂停、拖动进度、选择 `0.75×、1×、1.25×、1.5×、2×` 倍速，或按音频时间快进/快退 5 秒；跳转不超出录音范围，暂停时跳转保持暂停，到达末尾后结束播放。
4. 顶部返回、系统返回或返回手势均停止播放，回到此前列表范围、搜索条件与滚动位置，并收起底部播放器；不恢复进入详情前播放的其他录音。加载中返回不得在加载完成后自动播放。

自然播放结束后，播放状态回到未播放，进度回到起点；详情页不自动退出。切后台或锁屏不等同于返回列表，不触发“返回即停”，相关播放策略另行定义。

若文件因外部操作不可读，应用显示错误，不应让播放器停留在错误的播放状态，并提供移除失效索引的后续处理入口。

## 查找与整理

### 搜索录音

1. 用户进入搜索并输入标题关键词。
2. 列表即时或经短暂防抖后显示匹配当前范围的录音。
3. 用户清除关键词后，恢复原列表和排序。
4. 无匹配项时显示空结果状态，但不改变任何录音或文件夹数据。

### 创建文件夹并移动录音

1. 用户创建一个文件夹，并输入有效名称。
2. 应用创建逻辑文件夹；不要求用户为其选择真实磁盘路径。
3. 用户从录音操作菜单选择移动，并指定目标文件夹。
4. 应用更新录音所属分类，录音文件本身无需因为分类而移动。

### 重命名

1. 用户从录音操作菜单选择重命名。
2. 应用预填当前标题，用户修改并确认。
3. 应用更新显示标题和索引；底层音频文件名可由内部标识稳定管理，不以标题修改作为前提。

### 多选与批量操作

1. 用户点击顶部“多选录音”或长按录音行进入多选；长按时选中该条录音。
2. 点击录音行或复选框切换选择；“全选”仅选择当前文件夹与搜索条件下可见的录音，再次操作可取消全选。
3. 选择“移动”后指定目标文件夹，或选择“删除”并确认选中数量，整批录音移入最近删除。
4. 成功后退出多选并刷新列表；取消弹层或操作失败时保留选择，失败时显示提示供重试。若删除包含当前播放录音，先停止播放。
5. 改变搜索关键词、关闭搜索或切换文件夹时清空选择；退出按钮或系统返回退出多选。操作期间禁用选择与范围变更，避免重复提交。

此项仅包含普通列表的批量移动和软删除；最近删除中的批量恢复、永久删除随最近删除功能另行实现。

## 删除与恢复

### 移入最近删除

1. 用户选择删除一条录音。
2. 应用说明录音将移入最近删除，并在确认后标记为已删除。
3. 该录音不再出现在普通录音列表和搜索结果中，但在保留期内可恢复。

### 恢复或永久删除

1. 用户进入最近删除，查看已删除录音及剩余保留时间。
2. 选择恢复时，录音恢复到删除前的文件夹；原文件夹不存在时恢复至全部录音。
3. 选择永久删除时，应用二次确认后移除音频文件与索引，此操作不可撤销。
4. 到达 30 天保留期的录音由本地清理任务删除；清理失败时应在下次合适时机重试。

## 分享

1. 用户选择已完成录音的分享操作。
2. 应用以只读方式向系统分享面板提供 M4A 文件及合适的 MIME 类型；分享附件名使用录音列表中的标题，并保留 `.m4a` 扩展名。
3. 用户选择目标应用或取消分享。
4. 无论结果如何，丫丫录音中的文件、标题、文件夹和播放状态均不改变。

## 中断与返回

录音期间发生锁屏、切换应用、音频焦点丢失、存储空间不足或进程恢复等事件时，界面和通知栏反馈应以 [录音生命周期](../architecture/recording-lifecycle.md) 为准。用户返回应用后，必须能判断录音仍在进行、已暂停、已安全保存，还是因异常结束。
