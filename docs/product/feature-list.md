# 功能列表

本文定义丫丫录音首版（MVP）的产品范围和验收条件。它是开发前的功能基线，不等同于最终发布后的用户手册。

## 产品目标

用户应能在不登录、不联网的前提下，快速录下声音，并在设备本地可靠地查找、整理、回放和分享录音。应用不展示广告、不提供会员功能，也不收集或上传录音内容。

主要使用场景为几分钟的短时间录音。当前开发与发布验收以 1–5 分钟的代表性录音为主，另保留极短录音和操作/异常边界验证；一小时及更长录音的压力测试暂缓，不作为 REC-07 实现、参数选择或当前发布的必过关口。这里的时长是测试取样范围，不是应用录音时长上限。

## MVP 范围

当前新录音支持 AAC、MP3，初始默认 AAC，已有 M4A 保持兼容。REC-08 已实现，并按 2026-10-14 用户对设置、录音、播放、分享等功能的真机验收确认标为已完成，见 [验收反馈](../device-feedback.md#aac-功能验收确认2026-10-14)。REC-04、REC-07 和既有验收中的 M4A/MP3 描述保留历史基线，当前格式以 REC-08 为准。

| 编号 | 功能 | 验收条件 |
| --- | --- | --- |
| UX-06 | 主题模式 | 设置可选跟随系统、浅色模式、深色模式，初始默认跟随系统；选择即时保存并生效，重启保持。跟随系统响应系统主题变化；失败保留旧值并可重试。各页面、弹窗及系统栏保持可读，窄屏与大字体可操作，切换不影响录音会话与播放状态；通过自动化检查及 Android 真机视觉确认。 |
| UX-07 | 语言选择 | 设置可选简体中文、English，初始默认简体中文；保存成功立即切换，重启保持，失败保留旧值并可重试。页面、弹窗、提示、无障碍描述及录音通知随选择切换，英文准确自然且正确处理单复数。新保存录音的自动标题使用当前语言，已有标题及用户文件夹名保持。切换不重启活动录音或播放，窄屏/大字体可操作；通过自动化检查及 Android 真机验收。语言资源集中管理并可扩展。 |

### 录音

| 编号 | 功能 | 验收条件 |
| --- | --- | --- |
| REC-01 | 麦克风权限 | 首次录音前请求麦克风权限；未授权时明确说明无法录音，并允许用户再次请求或前往系统设置。 |
| REC-02 | 开始录音 | 用户可从主界面以单次操作开始录音；开始后显示明确的录音状态和已录时长。 |
| REC-03 | 暂停与继续 | 录音中可暂停，暂停后可继续写入同一条录音；暂停期间时长不增加。 |
| REC-04 | 停止并保存 | 停止操作完成后，录音按本次会话确定的 MP3 或 M4A 格式保存到本地；文件验证与索引提交成功后出现在录音列表中。M4A 使用 AAC-LC 编码，MP3 实时编码，停止后只完成剩余缓冲与文件收尾。 |
| REC-05 | 取消录音 | 用户可放弃尚未保存的录音；应用在明确确认后删除临时文件，且不在列表中留下记录。 |
| REC-06 | 异常保护 | 录音过程中遇到音频焦点丢失、应用切后台、存储异常或系统中断时，应用应依据 [录音生命周期](../architecture/recording-lifecycle.md) 尽力保存已经写入的内容，并向用户反馈结果。 |
| REC-07 | 默认录音格式与实时 MP3 | “更多 → 设置”可选择 MP3 或 M4A，初始默认 M4A；偏好即时保存且重启后保持，下次新建录音生效。MP3 直接由采集的 PCM 实时编码，不先录 M4A 再转换；两种格式均支持暂停/继续、停止、确认取消、播放及分享。当前会话格式固定，旧录音不转换；编码不可用或失败须明确反馈，不静默切换格式。通过自动化与 Android 真机验证，覆盖几分钟录音、极短录音边界、锁屏/后台、连续操作、异常与升级兼容。 |
| REC-08 | AAC / ADTS 原生输出 | 新录音设置提供 AAC、MP3，初始默认 AAC；原生直接输出 AAC-LC / ADTS 的 `.aac` 文件，不改后缀伪装或录后转码。升级将 M4A 默认偏好改为 AAC，保留 MP3 偏好；已有 M4A 文件、索引及草稿按原格式处理。AAC 支持暂停/继续、停止/取消、正确时长、播放/拖动/倍速及分享（`.aac` / `audio/aac`），会话格式固定。沿用保存和恢复协议，验证失败保留残留并反馈，不静默回退，首版不新增损坏尾帧修复。通过自动化与真机验收，覆盖升级、极短及 1–5 分钟录音、锁屏/后台和旧 M4A/MP3 回归。详见 [实现计划](../architecture/aac-adts-plan.md)。 |

### 录音浏览与回放

| 编号 | 功能 | 验收条件 |
| --- | --- | --- |
| LIB-01 | 录音列表 | 默认按创建时间倒序展示当前分类下的录音；每项至少显示标题、创建时间和时长。 |
| LIB-02 | 播放与暂停 | 用户可播放和暂停单条已完成录音；再次播放时界面正确反映播放状态。 |
| LIB-03 | 播放进度 | 用户可查看当前播放进度、拖动到指定位置，并显示总时长。 |
| LIB-04 | 倍速回放 | 详情页提供 0.75×、1×、1.25×、1.5×、2× 选项，正确应用并显示当前倍速；同一播放对象进入详情时保持倍速。 |
| LIB-05 | 搜索 | 用户可按录音标题搜索当前可见范围内的录音；空结果应有明确反馈。 |
| LIB-06 | 录音详情与播放入口 | 列表播放按钮使用简洁底部播放器；标题/行及底部播放器标题进入独立详情页并立即自动播放。同一播放对象保留进度，另一条停止原播放并切换；任意返回列表路径停止详情播放、收起底部播放器并恢复列表上下文，加载中返回不产生延迟播放。多选点击仅切换选择。 |
| LIB-07 | 快进与快退 | 详情页提供快进 10 秒与快退 5 秒，按音频时间跳转且不越过开头或末尾；暂停时跳转保持暂停，到达末尾后结束播放，不改变音频文件内容。 |

### 录音管理

| 编号 | 功能 | 验收条件 |
| --- | --- | --- |
| MGT-01 | 自动命名 | 新录音保存时生成基于本地日期和时间的默认标题，且用户可修改。 |
| MGT-02 | 重命名 | 用户可修改录音标题；修改后不改变音频内容、创建时间和所属文件夹。 |
| MGT-03 | 分享 | 用户可通过系统分享面板分享已完成的 MP3 或 M4A 文件；分享附件以录音标题命名，扩展名与 MIME 类型匹配实际格式，且不移动或删除本地原件。 |
| MGT-04 | 删除 | 删除操作需要确认；录音先移入最近删除，而非立即永久删除。 |
| MGT-05 | 最近删除 | 用户可查看、恢复和永久删除已删除录音；未恢复的录音默认保留 30 天后清理。 |
| UX-02 | 多选与批量操作 | 普通录音列表支持进入/退出多选、勾选与全选当前可见录音；可批量移动或经确认移入最近删除。批量操作在数据库事务内完成，失败不产生部分更新；不改变音频文件内容。 |

### 手动备份与恢复（2026-10-15 新增）

第一版采用一个未加密 ZIP，导出正常录音、元数据和全部文件夹（含空文件夹），排除最近删除、草稿及设置。导入合并，相同录音 ID 跳过（包括本地最近删除），无覆盖或副本选项。同 ID 文件夹沿用本地，不同 ID 同名时自动改名；现有顺序保持，新文件夹按备份顺序追加。新文件夹改用 UUID，旧 ID 保持。任务期间禁止业务数据修改并协调自动写入，浏览、播放与设置可用。详见 [第一版设计](../architecture/manual-backup-and-restore-design.md)及 [七步计划](../architecture/manual-backup-and-restore-implementation-plan.md)。

| 编号 | 功能 | 验收条件 |
| --- | --- | --- |
| BKP-01 | 备份契约与 ID 兼容 | 固定版本化 JSON/ZIP、相对路径和校验规则；新文件夹随机 UUID，旧 ID 与归属不变；非法条目及版本明确拒绝。 |
| BKP-02 | 任务协调与数据保护 | 单任务与录音互斥；手动管理、保存重放、恢复及过期清理均经过业务门禁；快照一致，取消/失败后可操作，浏览播放保持。 |
| BKP-03 | 文档访问与长任务 | URI 流式读写、选择取消、独立前台任务与通知、取消/重新进入和超时处理；任务与页面解耦，锁屏及平台行为通过真机验证。 |
| BKP-04 | ZIP 全量导出 | 导出范围正确，音频不转码；阶段字节进度及取消有效；包完整后才报告成功，失败清理半成品；大量文件与保存通过自动化/真机验证。 |
| BKP-05 | 合并导入与恢复 | 整包验证，冲突跳过、文件夹映射及路径重建正确；统一索引提交、取消和提交前后中断恢复保护原数据；重复导入及故障边界通过验证。 |
| BKP-06 | 备份恢复交互 | 设置入口、未加密说明、预览/进度/结果及保护提示完整；中英文、通知、浅深色、窄屏/大字体/无障碍与任务导航通过组件及真机验证。 |
| BKP-07 | 端到端验收 | 新设备恢复后标题、时间、文件夹与三格式播放正确；大量文件、冲突、损坏、空间不足、取消、后台/中断和既有功能回归均有验收证据。 |

## 数据与隐私边界

- 录音文件、文件夹和录音索引的工作数据保存在设备本地；用户可主动导出完整备份至所选位置，应用不直接接入云端服务。
- 文件夹是应用内的逻辑分类，不要求用户管理底层磁盘目录。
- 应用不要求账户登录，不使用广告 SDK，不进行行为追踪。
- 系统分享功能仅在用户主动触发后提供文件给目标应用。
- 备份 ZIP 第一版不加密，明确包含原始音频和元数据；导出到手机或交给分享目标不等于确认异地备份成功。
- 首版新录音目标为 MP3 与 AAC-LC/ADTS（REC-08 完成前为 MP3 与 M4A/AAC-LC），旧 M4A 保持兼容；编码完全在设备本地完成，不提供已有录音转换或云端同步。

## 首版不包含

- 云端备份、多设备同步、协作或账户体系。
- 自动/增量备份、加密备份、断点恢复、覆盖导入及冲突副本。
- 自动转写、内容识别、AI 摘要或在线分析。
- 波形编辑、裁剪、拼接、降噪等复杂音频编辑功能。
- MP3、AAC/ADTS 及旧 M4A 兼容之外的录音格式、已有录音的格式转换，以及高级采样率或码率设置。
- 嵌套文件夹、标签、收藏和智能分类。

## 发布前验收

首版至少应在目标 Android 版本与典型设备上验证以下结果：

1. 分别选择 MP3、M4A，连续执行开始、暂停、继续和停止后，可播放保存的录音，时长符合预期；格式偏好重启后保持，升级保留旧 M4A 文件与索引。
2. 录音时锁屏、切换应用或返回前台后，录音状态与文件结果符合录音生命周期规定。
3. 重命名、移动、删除、恢复和分享不会损坏原始音频文件。
4. 断网时，全部 MVP 功能仍可使用；应用不因网络不可用而阻塞。
5. 权限被拒绝、存储不足和系统中断时，用户能了解发生的情况，且已完成部分不会被静默丢弃。
6. MP3 在 1–5 分钟代表性录音中实时编码稳定，停止后无需重编码整段录音；检查音频连续性、时长、缓冲积压、内存和停止收尾耗时，并验证极短录音、编码/写入失败及进程被终止后的恢复结果，不承诺恢复未落盘的内容。一小时录音及长期 CPU/耗电趋势测试暂缓。
7. REC-08 完成后，新录音按 AAC、MP3 验收，并回归旧 M4A；确认实际 ADTS 封装、完整解码及播放定位可用，升级保留文件、草稿、元数据、文件夹及其他偏好。
8. 手动备份按 [第一版设计](../architecture/manual-backup-and-restore-design.md#10-验收要求)和 [七步计划](../architecture/manual-backup-and-restore-implementation-plan.md)完成新设备恢复、重复与冲突跳过、整包校验、数据保护、长任务和中断验收；失败不损坏已有库。
